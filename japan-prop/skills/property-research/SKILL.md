# 物件の調査・探索

jp-property-finder の `research_properties` が調査の手順をまとめて実行する。個別の検索ツールを組み合わせるより先に、これを使う。

## 0. 役割分担（Claude Code）

Claude Code では、物件の調査はサブエージェント `property-researcher`（プラグインでは `japan-prop:property-researcher`、モデルは Haiku）に任せる。

- メインのエージェント: 利用者から条件を聞き取る（AskUserQuestion など）。条件が少ないときは、エリア・予算・間取りや人数・必須条件を先に聞く。
- `property-researcher`: 受け取った条件で `research_properties` を実行して報告する。サブエージェントは利用者に質問できないので、聞き取りはメインのエージェントが済ませてから渡す。
- メインのエージェント: 報告を利用者に伝える。候補が少なければ、どの条件を緩めるか利用者に聞いて再調査する。

サブエージェントが使えない環境（Codex など）では、以下の手順を自分で行う。

## 1. 条件を決める

依頼から読み取り、足りない条件だけを聞く。決まらない条件は空のままでよい（制約なしとして扱われる）。

| 引数 | 内容 |
| --- | --- |
| `prefecture` / `municipalities` | 対象エリア。市区町村は複数指定できる（例: `["札幌市中央区", "札幌市北区"]`） |
| `category` | `賃貸`、`オフィス・事務所`、`マンション`、`戸建て`、`売地` など |
| `use_case` | `residence`（住まい）、`office`（一般オフィス）、`software_dev`（開発オフィス）。採点の重みと確認事項が変わる |
| `headcount_min` / `headcount_max` | オフィスの人数。1人3〜5坪として面積の範囲に直される |
| `max_monthly_cost` | 月額の上限（円）。賃貸は家賃、オフィスは共益費込み |
| `max_walk_min` | 駅徒歩の上限（分） |
| `must_have` / `exclude` | 掲載文に必要な語・除外する語（例: `["24時間"]`、`["定期借家"]`） |

## 2. 調査する

`research_properties` を1回呼ぶ。報告には次の項目が入る。

- **前提**: 人数から置いた面積など、ツールが置いた仮定
- **収集状況**: エリアごとのライブ検索の成否と、使ったデータの日付
- **絞り込み**: 何件集めて何件残ったか、どの条件で何件落ちたか
- **候補**: 点数・理由・要確認事項（面積の食い違い、極端な相場乖離、古いデータなど）
- **足りない範囲**、**確認事項**、**非公開物件の注意**、**次にやること**

## 3. 結果を見て動く

- 候補が少ないとき: 「いちばん多く除外した条件」を利用者に伝え、緩めるか聞いて再調査する。
- ライブ検索が失敗したとき: 過去データでの結果だと明示する。ネットワークのある環境での再調査を勧める。
- 気になる候補: `get_property_detail` で掲載元を確認する。`analyze_property_hazard_and_surroundings` で災害リスクと周辺施設を調べる。複数あれば `compare_properties_tool` で表にする。

## 4. 報告する

- 候補ごとに、点数の理由と要確認事項を添える。点数は掲載情報からの目安で、物件の良し悪しを断定しない。
- 前提・データの日付・足りない範囲を省かない。
- 確認事項（内見・問い合わせで聞くこと）を必ず添える。
- **非公開物件の注意を必ず伝える。** 日本には、不動産事業者（宅地建物取引業者）しか閲覧できない非公開物件がある。このツールで探せるのはポータルサイトに掲載された物件だけなので、希望エリアの不動産会社に条件を伝えて紹介してもらうよう勧める。
